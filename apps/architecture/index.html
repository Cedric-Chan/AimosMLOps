端到端故事线一个风控模型从数据到流量的旅程

1
数据与代码源

DS GitLab 算法工程仓提供实验代码与配置；有权限的 Hive 表（含 WideTable 产物）提供训练数据，由 Datasource 节点装载至 S3。

2
特征生产

Feature Store 五层组装 DataSource → FeatureSource → Transformation → FeatureGroup，FG 发布自动同步 FeatureMap；离线出口 WideTable。

3
模型训练

内部改造嵌入的 MLflow 承担训练迭代管理（Run 对比 / 指标 / 模型版本），与 Model Experiment 的 Experiment / Run 1:1 映射；Ray 集群执行，产物 / 日志 / 指标统一落 S3。

4
注册与交付

训练产物登记为 Model → ModelVersion → Build，经 Model Deployment 发布为在线推理服务。

5
在线服务

Online Runtime / Orches Service 承载实时推理；业务请求触发 FG Serving 在线特征检索，AI 资产经 AI Hub 供給 LLM Workflow。

关键机制跨模块怎么咬合

离在线一致性

FeatureGroup 绑定同一 Transformer Version 保障训练 / 服务同源加工，避免 Training / Serving Skew；训练经 WideTable Point-in-Time Join 取数。

MLflow 1:1 映射

Experiment / Run / 画布节点与 MLflow Experiment / Parent Run / Nested Run 一一映射；MLflow（内部改造嵌入）承担训练迭代管理与模型版本 lineage，产物统一存 S3，实验可追溯。

双特征流

离线流 Hive ODS → FS → WideTable 供训练；在线流 Kafka → HBase / Redis → FG Serving 供推理，同源分层、各自出口。
